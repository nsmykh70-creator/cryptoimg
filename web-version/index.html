Как это работает?

Многоуровневая архитектура защиты данных с AEAD-шифрованием и keyed-стеганографией.

🔄

Авто-конвертация

Любой исходный формат пере-сохраняется в lossless-контейнер (PNG/WebP/AVIF).

🛡️

AEAD: AES-256-GCM

PIN → Argon2id → HKDF → AES-256-GCM. Любое изменение ciphertext или header детектируется через auth tag.

🧩

Reed-Solomon ECC

Повреждённые пиксели при передаче восстанавливаются. ECC дополняет (не заменяет) аутентификацию.

🌐

Оффлайн

Все вычисления локально в браузере через Web Crypto API. Сервер не видит ваши данные.

Частые вопросы

Почему используется ПИН-код (8-11 цифр), а не пароль?

Запомнить 8–11 цифр проще, чем 24 английских слова Seed-фразы. Без ПИН-кода извлечь данные невозможно — даже зная, что в фото есть стеганография.

Argon2id (RFC 9106, m=64MiB, t=3, p=4):

Каждая попытка ПИН-кода требует 64 МБ RAM и 3 итерации. Это делает GPU/ASIC-брутфорс экономически невыгодным. v5 также использует HKDF для разделения ключей шифрования и стеганографии.

Что изменилось в v5 по сравнению с v4?

Полная переработка крипто-ядра: AES-CBC заменён на AES-256-GCM (аутентифицированное шифрование), добавлен HKDF для domain separation (отдельные ключи для шифрования и стеганографии), стеганография стала keyed (позиции пикселей псевдослучайны, зависят от PIN), добавлен self-test перед выдачей фото-ключа, проверка BIP39 checksum, и расширенный authenticated header.

У меня фото в формате JPEG/HEIC. Оно подойдёт?

Да! Загрузите любой формат — браузер распакует. При сохранении сервис принудительно использует lossless-контейнер (PNG/WebP/AVIF), чтобы скрытые данные не потерялись.

Что не так с AVIF?

AVIF даёт отличное сжатие, но не все старые браузеры умеют кодировать его lossless. Если кодирование не удастся — Cryptoimg безопасно сохранит PNG, уведомив вас.

Можно ли отправить фото-ключ через Telegram?

Только как «Файл» (Скрепка → Отправить как файл). Обычная отправка применит сжатие и уничтожит данные. Reed-Solomon восстанавливает мелкие повреждения, но не сильное сжатие.
